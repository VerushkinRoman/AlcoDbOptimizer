# backup-restore Specification

## Purpose
Сохраняет данные пользователей перед удалением в локальные JSON-файлы и позволяет найти нужный бэкап, восстановить даты календаря и запись реестра.

## Requirements

### Requirement: Бэкап записывается в локальный каталог

Бэкап SHALL создаваться в локальном каталоге `backups` как JSON-файл с именем `backup_<prefix>_<timestamp>.json`, где `timestamp` — время создания в миллисекундах. Для удаления содержимое — один пользователь или список пользователей; для очистки реестра — список email-записей.

#### Scenario: Бэкап одного пользователя

- **WHEN** удаляется один зарегистрированный пользователь
- **THEN** создаётся файл с его идентификатором в имени и JSON-объектом пользователя внутри

#### Scenario: Бэкап группы пользователей

- **WHEN** выполняется массовое удаление или очистка реестра
- **THEN** создаётся файл с общим префиксом операции и JSON-массивом записей

### Requirement: Список бэкапов собирается из файлов

Экран восстановления SHALL читать все файлы `backup_*.json`, поддерживать как массив, так и одиночный объект, и показывать по одной записи на каждого пользователя. Записи сортируются от новых к старым по времени из имени файла.

#### Scenario: В каталоге несколько бэкапов

- **WHEN** пользователь открывает восстановление
- **THEN** отображаются все корректные записи, отсортированные по времени удаления по убыванию

#### Scenario: Повреждённый файл

- **WHEN** один из JSON-файлов не удаётся разобрать
- **THEN** он пропускается, а остальные записи остаются доступными

#### Scenario: Файл очистки реестра

- **WHEN** файл содержит массив email-записей реестра, а не пользователей
- **THEN** он остаётся в каталоге, но не отображается в списке восстановления

### Requirement: Бэкап можно отфильтровать и выбрать

Список SHALL фильтроваться по части идентификатора пользователя без учёта регистра. Восстановление доступно только после выбора конкретной записи.

#### Scenario: Фильтр по email

- **WHEN** пользователь вводит часть email в фильтр
- **THEN** остаются только записи, чей идентификатор содержит эту подстроку

#### Scenario: Запись не выбрана

- **WHEN** открыт список бэкапов и ни одна запись не выбрана
- **THEN** кнопка восстановления недоступна

### Requirement: Восстановление возвращает даты календаря

Восстановление SHALL записывать даты из бэкапа в документ `Dates` пользователя с объединением существующих полей. Для каждой даты сохраняется её номер дня; тип отметки `drinkType` в бэкапе отсутствует и не восстанавливается.

#### Scenario: Восстановление дат

- **WHEN** пользователь подтверждает восстановление записи
- **THEN** в `Dates` появляются все даты из бэкапа, а существующие поля документа сохраняются

#### Scenario: Тип отметки после восстановления

- **WHEN** даты восстановлены из бэкапа
- **THEN** исходный тип `Full` или `Half` не возвращается, потому что бэкап хранит только даты

### Requirement: Восстановление возвращает данные реестра

Если в бэкапе есть данные реестра, система SHALL восстанавливать никнейм, email, локаль, токен и сумму донатов в `Collection_of_all_users/Users`.

#### Scenario: Бэкап зарегистрированного пользователя

- **WHEN** восстанавливается пользователь с сохранёнными данными реестра
- **THEN** запись реестра создаётся или обновляется значениями из бэкапа

#### Scenario: Бэкап без данных реестра

- **WHEN** в записи нет данных реестра
- **THEN** восстанавливаются только даты календаря

### Requirement: Восстановление не восстанавливает Auth

Восстановление MUST NOT создавать пользователя Firebase Auth, восстанавливать пароль или другие учётные данные. Исходный файл бэкапа после восстановления не удаляется.

#### Scenario: Восстановление удалённого аккаунта

- **WHEN** пользователь восстанавливает зарегистрированную запись
- **THEN** даты и реестр восстанавливаются, но войти в аккаунт без отдельного создания Auth-пользователя нельзя

#### Scenario: Повторное восстановление

- **WHEN** восстановление выполнено успешно
- **THEN** файл бэкапа остаётся в каталоге и может быть использован снова

### Requirement: Ошибка восстановления не скрывается

При ошибке записи дат или реестра система SHALL показывать сообщение об ошибке и оставлять диалог восстановления открытым. Прогресс восстановления блокирует повторное подтверждение.

#### Scenario: Ошибка записи

- **WHEN** Firestore возвращает ошибку во время восстановления
- **THEN** пользователь видит сообщение об ошибке, а выбранная запись остаётся выбранной

#### Scenario: Восстановление уже выполняется

- **WHEN** операция восстановления активна
- **THEN** повторное нажатие кнопки восстановления не запускает вторую операцию
