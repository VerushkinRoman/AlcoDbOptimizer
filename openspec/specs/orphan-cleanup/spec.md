# orphan-cleanup Specification

## Purpose
Находит и удаляет записи, которые остались после пользовательских данных: email в глобальном реестре без коллекции и пользователей Firebase Auth без календаря.

## Requirements

### Requirement: Осиротевшая запись реестра определяется по отсутствию коллекции

Запись реестра SHALL считаться осиротевшей, если её email отсутствует среди пользовательских root-коллекций. Служебные коллекции в это сравнение не входят. Экран показывает число осиротевших записей и общее число записей реестра.

#### Scenario: Email есть в реестре, но коллекции нет

- **WHEN** email присутствует в `Collection_of_all_users/Users`, но коллекция с таким id отсутствует
- **THEN** email попадает в список осиротевших

#### Scenario: Коллекция существует

- **WHEN** для email есть пользовательская коллекция
- **THEN** запись реестра не считается осиротевшей

### Requirement: Список осиротевших записей можно фильтровать

Осиротевшие email SHALL отображаться списком и фильтроваться по подстроке без учёта регистра. Фильтр не меняет набор данных для массового удаления.

#### Scenario: Фильтр по домену

- **WHEN** пользователь вводит часть email в фильтр
- **THEN** список показывает только совпадающие записи

#### Scenario: Фильтр не скрывает данные от удаления всех

- **WHEN** применён фильтр и пользователь нажимает `Remove All`
- **THEN** удаляются все осиротевшие записи, а не только видимые в фильтре

### Requirement: Удаление записи реестра необратимо

Удаление одной записи SHALL сразу удалять email из `Collection_of_all_users/Users` без дополнительного подтверждения. Перед удалением всех записей SHALL создаваться локальный бэкап со списком удаляемых email.

#### Scenario: Удаление одной записи

- **WHEN** пользователь нажимает `Remove` рядом с email
- **THEN** запись удаляется из реестра и исчезает из списка

#### Scenario: Массовое удаление

- **WHEN** пользователь нажимает `Remove All`
- **THEN** сначала создаётся бэкап, затем удаляются все осиротевшие записи

### Requirement: Осиротевший пользователь Auth определяется по отсутствию коллекции

Пользователь Firebase Auth SHALL считаться осиротевшим, если его email отсутствует среди пользовательских root-коллекций. Пользователи Auth без email в список не попадают.

#### Scenario: Auth-пользователь без календаря

- **WHEN** email пользователя Auth не совпадает ни с одной пользовательской коллекцией
- **THEN** email попадает в список осиротевших Auth-пользователей

#### Scenario: У Auth-пользователя нет email

- **WHEN** запись Firebase Auth не содержит email
- **THEN** она не отображается в списке и не удаляется этой операцией

### Requirement: Удаление Auth-пользователей необратимо и не создаёт бэкап

Удаление одного или всех осиротевших Auth-пользователей SHALL удалять их из Firebase Auth без локального бэкапа. После успешного удаления запись исчезает из списка, а интерфейс сообщает количество удалённых.

#### Scenario: Удаление одного Auth-пользователя

- **WHEN** пользователь нажимает `Delete Auth` рядом с email
- **THEN** пользователь удаляется из Firebase Auth и исчезает из списка

#### Scenario: Массовое удаление Auth

- **WHEN** пользователь нажимает удаление всех осиротевших Auth-пользователей
- **THEN** система удаляет доступные записи и показывает количество успешно удалённых

### Requirement: Ошибки очистки не блокируют остальные записи

Ошибка удаления одной записи SHALL не прерывать массовую операцию. При ошибке загрузки списка интерфейс показывает сообщение и не запускает удаление.

#### Scenario: Одна запись не удалилась

- **WHEN** удаление email завершилось ошибкой во время массовой операции
- **THEN** остальные записи продолжают удаляться

#### Scenario: Не удалось прочитать реестр

- **WHEN** список коллекций или реестр недоступен
- **THEN** показывается ошибка чтения, а список осиротевших не считается пустым результатом
