# user-deletion Specification

## Purpose
Удаляет неактивных пользователей вместе со связанными данными в Firestore, Firebase Auth и реестре, сохраняя зарегистрированных пользователей в локальный бэкап до необратимой операции.

## Requirements

### Requirement: Зарегистрированный пользователь сохраняется перед удалением

Перед удалением зарегистрированного пользователя система SHALL записывать его данные в локальный бэкап. Анонимные пользователи в бэкап не попадают.

#### Scenario: Удаление одного зарегистрированного пользователя

- **WHEN** пользователь подтверждает удаление зарегистрированной учётной записи
- **THEN** сначала создаётся локальный бэкап с её датами и данными реестра, затем выполняется удаление

#### Scenario: Удаление анонимного пользователя

- **WHEN** пользователь подтверждает удаление анонимной учётной записи
- **THEN** бэкап не создаётся, а удаление выполняется сразу после подтверждения

### Requirement: Удаление каскадно затрагивает связанные данные

Удаление SHALL удалять пользовательскую коллекцию, затем связанную запись Firebase Auth. Для зарегистрированного пользователя также удаляется запись в реестре `Collection_of_all_users/Users`.

#### Scenario: Удаление зарегистрированного пользователя

- **WHEN** удаляется коллекция зарегистрированного пользователя
- **THEN** после неё удаляются запись реестра и пользователь Firebase Auth с тем же email

#### Scenario: Удаление анонимного пользователя

- **WHEN** удаляется коллекция анонимного пользователя
- **THEN** после неё удаляется пользователь Firebase Auth по идентификатору коллекции

#### Scenario: Коллекция уже удалена

- **WHEN** пользовательская коллекция отсутствует, но запись в Auth или реестре осталась
- **THEN** удаление связанной записи всё равно выполняется

### Requirement: Удаление одного пользователя требует подтверждения

Удаление из карточки пользователя SHALL выполняться только после отдельного подтверждения. После успешного удаления пользователь исчезает из локального списка неактивных.

#### Scenario: Подтверждение удаления

- **WHEN** пользователь открывает карточку и подтверждает удаление
- **THEN** операция запускается, а после успеха карточка закрывается и запись исчезает из списка

#### Scenario: Отмена удаления

- **WHEN** пользователь закрывает диалог подтверждения без удаления
- **THEN** данные во Firestore и локальный список не меняются

### Requirement: Удаление всех обрабатывает весь список

`Delete All` SHALL удалять всех найденных неактивных пользователей, кроме служебных коллекций, и обновлять прогресс после каждого пользователя. Ошибка удаления одного пользователя не прерывает обработку остальных.

#### Scenario: Массовое удаление

- **WHEN** пользователь подтверждает удаление всех неактивных
- **THEN** система последовательно удаляет пользователей и показывает прогресс `удалено / всего`

#### Scenario: Ошибка на одном пользователе

- **WHEN** удаление одной учётной записи завершается ошибкой
- **THEN** остальные пользователи продолжают удаляться, ошибка фиксируется в журнале, а неудалённая запись остаётся в списке

### Requirement: Неудалённые пользователи доступны для повтора

Записи, которые не удалось удалить при массовой операции, SHALL оставаться в локальном списке и отображаться отдельным списком с количеством. Повторная попытка MUST обрабатывать только оставшихся пользователей.

#### Scenario: Частичный успех

- **WHEN** часть записей не удалена
- **THEN** интерфейс показывает список неудалённых записей и кнопку повтора

#### Scenario: Повторная попытка

- **WHEN** пользователь нажимает «Повторить»
- **THEN** удаление запускается для оставшихся записей, а итог снова показывает количество успешных и неудалённых

### Requirement: Список неудалённых экспортируется в файл

Интерфейс SHALL позволять сохранить список неудалённых записей в CSV-файл. Файл MUST содержать заголовок `user_id` и по одной записи на строку. После успешной записи путь к файлу MUST отображаться пользователю.

#### Scenario: Экспорт списка

- **WHEN** пользователь нажимает «Экспорт списка» в диалоге неудалённых записей
- **THEN** создаётся CSV-файл в папке бэкапов, а путь к нему показывается в диалоге

#### Scenario: Ошибка записи

- **WHEN** файл не удалось создать или записать
- **THEN** пользователь видит сообщение об ошибке, а список неудалённых записей не меняется

### Requirement: Служебные коллекции не удаляются

Операции удаления MUST NOT удалять коллекции из списка служебных. При попытке удалить такую коллекцию операция завершается без удаления данных.

#### Scenario: Служебная коллекция попала в список

- **WHEN** идентификатор пользователя совпадает со служебной коллекцией
- **THEN** удаление этой коллекции не выполняется

### Requirement: Результат удаления сообщается пользователю

После завершения операции интерфейс SHALL показывать итог: количество удалённых записей или сообщение об ошибке. Во время удаления повторный запуск удаления и сканирования MUST быть заблокирован.

#### Scenario: Успешное массовое удаление

- **WHEN** все записи обработаны
- **THEN** показывается точное число успешно удалённых записей, а список неактивных содержит только неудалённые записи

#### Scenario: Удаление уже идёт

- **WHEN** операция удаления активна
- **THEN** кнопки удаления и сканирования недоступны до её завершения
